03 · dominio/aviso.py

El aviso controla su propio ciclo de vida

self._estado = _PENDIENTE
self._notas = []
self._descarte = None

def descartar(self, operador_id, justificacion, fecha_hora):
    siguiente = self._estado.descartar()
    descarte = Descarte(operador_id, justificacion, fecha_hora)
    registro = Registro.de(
        operador_id, fecha_hora,
        Operacion.AVISO_DESCARTADO, self._id
    )
    self._descarte = descarte
    self._estado = siguiente
    self._registros.append(registro)

¿Qué hace?

Un aviso nace pendiente. Puede aceptar notas, ser aceptado o descartado. Al descartar, primero valida el estado y construye los datos; recién después modifica el objeto.

Conceptos POO

EncapsulamientoStateValidación
El estado decide si la operación está permitida. Un aviso ya aceptado no puede volver a descartarse.
04 · dominio/mision.py

Una misión, distintas especializaciones

class Mision(ABC):
    @abstractmethod
    def verificar_vehiculo(self, vehiculo):
        ...

    @abstractmethod
    def verificar_equipamiento(self, unidad):
        ...

class Evacuacion(Mision):
    def verificar_vehiculo(self, vehiculo):
        vehiculo.verificar_evacuacion(self._cantidad)

class Rescate(Mision):
    def verificar_vehiculo(self, vehiculo):
        vehiculo.verificar_rescate()

class AsistenciaSanitaria(Mision):
    def verificar_vehiculo(self, vehiculo):
        vehiculo.verificar_asistencia()

¿Qué hace?

Mision define el contrato común. Las clases concretas implementan los requisitos propios de evacuación, rescate y asistencia sanitaria.

Conceptos POO

AbstracciónHerenciaPolimorfismo
El resto del sistema trabaja con una referencia Mision sin necesitar preguntar qué clase concreta recibió.
05 · dominio/unidad.py + vehiculos.py

La unidad verifica si puede responder

def comprometer(self, mision):
    self._condicion.verificar_habilitada()
    if self._mision_id is not None:
        raise UnidadOcupada(...)
    self._vehiculo.verificar_operativo()
    mision.verificar_vehiculo(self._vehiculo)
    mision.verificar_personal(self.personal)
    mision.verificar_equipamiento(self)
    self._mision_id = mision.id

¿Qué hace?

Antes de reservar la unidad, comprueba que esté habilitada, libre y que tenga vehículo, personal y equipamiento compatibles.

¿Dónde aparece el polimorfismo?

La misión consulta al vehículo mediante métodos como verificar_rescate() o verificar_evacuacion(). Cada tipo de vehículo responde según sus capacidades.

06 · dominio/flota.py + emergencia.py

Consistencia global y cierre seguro

Flota · recursos únicos

for persona in unidad.personal:
    self._exigir_persona_libre(persona.id, None)

self._exigir_vehiculo_libre(unidad.vehiculo.id, None)

for equipo in unidad.equipamiento:
    self._exigir_equipo_libre(equipo.id, None)

self._unidades[unidad.id] = unidad

La flota controla todas las unidades para impedir que una persona, vehículo o equipo quede asignado a dos.

Emergencia · cierre

def cerrar(self, misiones):
    misiones = tuple(misiones)
    for mision in misiones:
        mision.verificar_concluida()
    if not any(m.es_exitosa() for m in misiones):
        raise SinMisionExitosa(...)
    return _CERRADA

No se puede cerrar si hay misiones sin concluir. Además, exige al menos una misión finalizada satisfactoriamente.

Las reglas que involucran a varios objetos se ubican en el componente que puede garantizar la consistencia.
07 · historial.py + errores.py

Registrar lo ocurrido y explicar los rechazos

@dataclass(frozen=True, slots=True)
class Registro:
    actor_id: str
    fecha_hora: datetime
    operacion: Operacion
    recursos: tuple[str, ...]
    detalle: tuple[tuple[str, str], ...] = ()

    @classmethod
    def de(cls, actor_id, fecha_hora, operacion,
           *recursos, **detalle):
        return cls(
            actor_id, fecha_hora, operacion,
            tuple(recursos),
            tuple((k, str(v)) for k, v in detalle.items())
        )

Historial

Registro es inmutable: identifica quién hizo qué, cuándo y sobre qué recursos. Los agregados exponen sus registros como tuplas.

Errores del dominio

errores.py define excepciones específicas, por ejemplo UnidadOcupada, PersonalInsuficiente o VehiculoIncompatible.

08 · reglas compartidas y pruebas

Cómo se comprueba que el diseño funciona

Archivos de soporte

  • catalogos.py: enums para tipos, estados y competencias.
  • valores.py: Ubicacion y validaciones comunes.
  • distribucion.py: busca si personas distintas cubren los puestos requeridos.
  • personal.py, equipamiento.py y vehiculos.py: modelan los recursos.

Pruebas automatizadas

uv sync
uv run pytest

Los tests verifican avisos, asignaciones, ejecución, emergencias y recursos. test_diseno.py controla reglas de arquitectura: sin isinstance/type, solo biblioteca estándar y sin consultar la hora del sistema.

El README del repositorio indica 204 pruebas aprobadas.
